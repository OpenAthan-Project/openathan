# v0.6.0 preparation — 2026-10-14

This prepares the next Atom and Waveshare Box V2 release for review. The public
stable release remains v0.5.0. No release tag, GitHub release upload, publication,
website adoption or new device installation is performed by this preparation.
See the [candidate notes](../releases/v0.6.0.md) and [release procedure](releases.md).

## Source and compatibility

The candidate combines the already merged Quran streaming/error handling,
Atom volume/Stop improvements and always-visible Waveshare prayer ring.
Preparation changes only the official and inherited Waveshare project versions,
`release/firmware.json` and documentation. No firmware logic, dependencies,
recordings, HTTP API or persistence format changes are introduced here.

Measured baseline: `460a791434329b285029a7304631931c95cd50a4`, the hardware
documentation branch with unchanged v0.5.0 production firmware.
Measured candidate: `ae1db1037ce383211e9d8eda8ff36478bee0d313`, carrying the
v0.6.0 identity and candidate notes. Both production boards use that same exact
candidate source. Subsequent preparation-report edits do not change firmware
inputs. These are branch-source preview artifacts: after review and merge, rebuild
the exact selected main source before tagging or uploading a release.

The upgrade schema, settings/storage compatibility and shared-audio format remain
1. Each board retains both 2 MiB application slots and the separate 3.5 MiB shared
audio partition. Existing Atom calibrated-volume companion/mirror behavior and
its older-firmware compatibility retain their source-bound validation.

## Checks before publication

1. Review and merge the hardware-evidence and version/preparation PRs. Select an
   exact source on main and require its latest main-push Firmware CI to pass.
2. Rebuild both production images from that exact source, package the approved
   shared recordings and sign with the existing production key. Revalidate the
   hardware/source/version identities, signatures, factory/OTA agreement,
   checksums, capacity, source-bound audio validator and pinned installer contract.
3. Review the evidence boundaries above against the selected candidate. Any
   additional device session must be separately coordinated with fresh device
   identification, owner presence for listening, current state preservation and
   compatible application-only recovery. Exact signed-candidate installation and
   update/rollback evidence has not been collected here.
4. Resolve or explicitly assess remaining coverage: newer-source full scheduled
   Atom playback, longer repeated Quran streaming/clean runtime memory, Quran
   interactions with firmware maintenance, physical Wi-Fi/restart listening gaps,
   and other recordings/channel counts. New maximum Atom distortion, RTC battery
   retention/drift, other panel lots and optional peripherals remain unqualified.
5. After applicable validation and review, create an unused tag on that exact
   qualified main source and upload a verified draft using the release procedure.
   Stable/latest publication requires separate explicit approval. Verify public
   delivery and website adoption afterward. Publication does not queue updates
   on existing speakers; owners choose their own preserving update.

This report schedules no additional hardware session. Earlier failures, missed
listening samples and dated automated/device results are preserved. Static RAM,
successful builds and a signed preview bundle do not establish runtime headroom,
audible acceptance or public release readiness.
