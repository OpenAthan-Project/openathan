# v0.8.0 preparation — 20 October 2026

This candidate adds the approved dua to fresh-install bundles and the signed,
version-bound Wi-Fi media feed. It includes a reliability fix for shared
playback/installation ownership: manual firmware checks and installations return
busy, automatic checks remain due, and conflicting USB provisioning or first-run
enrollment waits. USB network repair remains available while an update is merely
queued. Production trust, the partition table, both application slots, the
two-track header and normal/Fajr recording bytes remain unchanged.

Attended preparation exposed a retained empty USB update journal blocking Atom
provisioning before audio startup health. Empty legacy journals now relinquish
USB ownership at load without a storage write; new clears use the ordinary
empty journal format. A queued descriptor or handoff marker retains its existing
ownership and health/selection checks. Regression tests cover both old and new
empty records before health confirmation, and cancellation followed by reboot.

The [release notes](../releases/v0.8.0.md) describe owner behavior. The
[attended validation](dua-attended-validation-2026-10-20.md) reconciles accepted
listening, Stop, offline and interrupted-download results from 19–20 October.
Those source-bound results precede this admission fix. The original failed and
missed attempts remain private evidence; they are not counted as passes.

## Runtime and release gates

The [bounded runtime report](dua-runtime-validation-2026-10-20.md) records two
scheduled normal Athan–dua sequences per board over 35 minutes, with concurrent
authenticated status requests, private HTTPS installation and busy-admission
probes. Atom used source `5db9be6` and the existing upgrade qualification profile;
Waveshare used `7e3f2b2` and dua qualification with firmware updates disabled.
Both retained readiness without an observed playback error, scheduler fault or
restart. Largest internal blocks recovered to the same idle median; recovered
free-internal medians changed by -184 bytes on Atom and -140 on Waveshare.
These short private-profile samples do not establish long-term leak freedom,
production-origin TLS headroom or a direct worst-case scheduler continuity bound.
Waveshare OTA-worker hardware coverage remains untested.

Both original applications and complete audio were restored and independently
read back, retaining current production settings/history. Exact signed release
installation, update and recovery remain separate qualification gates. The
signed local review bundles above have not been uploaded or published.
