# v0.10.0 release preparation

This candidate includes saved speaker names from PR #67 and the local speaker
finder from PR #68. The source baseline is merged main
`91abee8c30200853b7953c06b001a8f6ab7ad4a7`. The qualification builds use
`1dfd0f0829b506f33cdc5015070b4da40505cf79`, which changes the version to v0.10.0

## Physical qualification

The available test unit is the connected Waveshare Box V2 with USB identity
`84:c7:bb:60:1c:54`, advertising `openathan-601c54.local`. Authenticated status
identified production v0.7.0 at source
`9d7e87ce2a438bb7805967059ed3264a46cf273b`, active setup, a synchronized clock,
automatic scheduling ready and no scheduler fault.

The owner approved a remote preserving update. A read-only provisioning status
request timed out. The subsequent recovery capture stopped because esptool
received no serial data while entering the bootloader with its supported
native-USB reset sequence. No flash write began and no recovery read completed.
Authenticated status afterward confirmed the same installed version, settings,
revision, consumed-prayer history, light/display preferences and time format.
Scheduling remained ready with no fault.

Candidate installation, flash/audio preservation checks, iPhone Safari and
Android Chrome discovery, restart, power-loss takeover, packet capture and
runtime memory measurements remain pending. The owner is away from the device,
so physical bootloader entry, phone and power checks need a later session.

Follow the [speaker discovery checklist](../../firmware/esphome/provisioning/HARDWARE_TEST.md#speaker-discovery)
for the remaining checks. A second updated speaker is needed for takeover
between physical speakers.
