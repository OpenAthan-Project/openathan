## Physical qualification: Box V2, 2026-11-11

The available test unit is the connected Waveshare Box V2 with USB identity
`84:c7:bb:60:1c:54`, advertising `openathan-601c54.local`. Authenticated status
identified production v0.7.0 at source
`9d7e87ce2a438bb7805967059ed3264a46cf273b`, active setup, a synchronized clock,
automatic scheduling ready and no scheduler fault.

The first connection attempt stopped before any flash write because USB returned
no serial data. A subsequent USB connection reset restored the application
protocol. Fresh USB identification confirmed the same MAC, registered hardware,
16 MiB flash, supported security configuration and recognized rollback bootloader.
Two complete before-update flash reads matched; the selected v0.7.0 application
was slot 0, sequence 3, VALID. Recovery data was retained privately outside Git.

The owner-approved signed USB updater verified the descriptor, acknowledged all
1,425,392 application bytes and verified v0.10.0 before selecting the inactive
slot. A USB restart with DTR released booted the candidate at
`1dfd0f0829b506f33cdc5015070b4da40505cf79`. Application health became confirmed;
the clock and automatic scheduler were ready with no scheduler fault. This was a
signed USB update, not a Wi-Fi OTA transport test.

Two complete after-update 16 MiB reads also matched. The selected candidate was
slot 1, sequence 4, VALID, with application SHA-256
`de0433aa8c73b4fe7b5faed00fef8ed6c571e1cb9f519b100e73b5f5f4cd4dbd`.
Independent flash comparisons preserved the bootloader, partition table, old
application slot, shared audio and unused flash. CRC-validated settings,
consumed-prayer history, Wi-Fi/password, setup and preference record payloads
matched the baseline, including the existing update-journal payload. The only
additional durable record was the speaker-name record created by the save/clear
test below; OTA selection metadata changed as expected. The device was restarted
into normal operation after readback.
Final USB status confirmed candidate health with no queued update. Ten further
finder/authenticated-status request pairs passed with scheduling ready and no
fault. Settings, their revision, prayer history, setup, time format and display/
light preferences still matched the fresh v0.7.0 baseline.

### Observed discovery and browser behavior

- The operating system resolved `openathan.local` to the updated Box. The live
  directory listed the Box once and two older official speakers by short ID.
- The shared host returned the directory, rejected settings/provisioning routes
  and denied a control POST. The canonical speaker host still required its
  password; authenticated settings remained accessible with the existing password.
- Saving a temporary speaker name updated the live directory. Chromium opened
  the directory and followed its link to the authenticated speaker page, whose
  title and heading used that name. The directory had no horizontal overflow at
  390px and 960px widths.
- The saved name persisted through a further USB restart. After at least 45
  seconds of healthy operation, the already-open Chromium finder tab reloaded
  successfully and listed the speaker once with its saved name. Clearing the
  name restored its original empty value; prayer/settings revisions and values
  remained unchanged. The separate speaker-name revision advanced during testing.

Playwright WebKit could not open the local address and reported an offline
connection. Native Safari verification then stopped because the Mac was locked.
Neither attempt establishes an iPhone Safari result or a firmware defect.

### Playback and runtime memory

The [focused Box V2 playback and memory report](discovery-playback-memory-2026-11-11.md)
records clean-candidate Play/Stop/replay while using the finder, with owner
listening confirmation and unchanged settings/history. A temporary read-only
probe on the same source then measured heap integrity, available internal RAM,
PSRAM and worker-stack headroom during the same workload. Both runs passed all
29 finder/status request pairs without a restart or playback error. The memory
numbers are diagnostic-image observations with stated probe overhead and limits.
The exact clean-candidate application slot was restored afterward. Full 16 MiB
readback matched the fresh pre-probe backup; final status confirmed healthy
operation, ready scheduling and preserved settings/history with the probe removed.

### Remaining qualification

The three production profiles have automated build/package coverage. Physical
update and discovery evidence is from this representative Box V2; physical
testing of all three hardware models is not required for this shared change.
iPhone Safari and Android Chrome checks, WAN-disconnected browsing, physical
power-loss takeover, simultaneous startup/conflict and network-rejoin cases,
and multicast handoff capture remain pending. The focused playback and memory
checks above cover a bounded workload; the clean production image itself does
not expose detailed runtime counters.

Follow the [speaker discovery checklist](../../firmware/esphome/provisioning/HARDWARE_TEST.md#speaker-discovery)
for the remaining checks. A second updated speaker is needed for takeover
between physical speakers.
